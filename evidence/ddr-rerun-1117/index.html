Most beneficial measured issue: repeated selector searches

The i.MX6 CPU profile identifies repeated component-tree searches during phase planning; Group_getRoutingPhasePlans accounts for366.59s inclusive in the624.46s profiled initialization. Each phase/bus selector was resolved again for every candidate trace, and pin aliases also repeatedly resolved each trace's ports. The fix caches both for one planning invocation, with selectors keyed by subcircuit. Later calls resolve the current tree again. Native endpoint matching, aliases, phase ambiguity errors and scope tests pass.

The routed16-bit memory-bus repro records984 →96 selector searches, a90.2% reduction. Its copper is identical; the measured count updates in the same native PCB snapshot. The repro and fix are separate PRs. The real-board routed results below retain the same 600s total budget. OrangeCrab publishes partial plane copper only in the after run: its plane stage finishes at about 592s, close to the limit. The router and first-phase input are unchanged, so this timing-sensitive copper difference is not claimed as an algorithmic routing improvement. Incomplete or dirty copper is not counted as success.
