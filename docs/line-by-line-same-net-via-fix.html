Same-net via cleanup, line by line

This page explains the meaningful code in the fix. It skips imports, class boilerplate, and UI noise. The core idea: use ConnectivityMap when deciding whether copper belongs to the same electrical net.

Problem

The route had vias that looked like crossings. They were same-net, but the via-removal solver treated sibling same-net routes like blockers.

Mistake

The old logic mostly trusted route id equality. But two different route ids can still be one electrical net.

Fix

Compare route ids through connMap. Same-net copper is not a blocker for via-removal collision checks.

1. Route-to-route same-net check

This replaces a hard-to-read chain of OR conditions. It turns each route into a small list of possible ids, then asks if any pair is the same id or connected by connMap.

routeIsSameNet 
const routeIsSameNet = (
  route: HighDensityRoute,
  otherRoute: HighDensityRoute,
  connMap: ConnectivityMap,
): boolean => {
  const routeIds = [route.connectionName, route.rootConnectionName].filter(
    (id): id is string => id !== undefined,
  )
  const otherRouteIds = [
    otherRoute.connectionName,
    otherRoute.rootConnectionName,
  ].filter((id): id is string => id !== undefined)

  return routeIds.some((routeId) =>
    otherRouteIds.some(
      (otherRouteId) =>
        otherRouteId === routeId ||
        connMap.areIdsConnected(otherRouteId, routeId),
    ),
  )
}

Line 1-5: plain function, not a class method. It only needs inputs.

routeIds: current route name plus root route name if present.

otherRouteIds: same list for the possible blocker route.

filter: removes undefined root names and tells TypeScript the array is strings.

some + some: compare every id pair without writing a giant boolean expression.

equal id: exact same route/root means same net.

connMap: different ids can still be electrically connected.

2. Obstacle-to-route same-net check

Obstacles can be pads or copper features. If an obstacle is on the same net as the route, it should not block via-removal collision checks.

obstacleIsSameNet 
const obstacleIsSameNet = (
  obstacle: Obstacle,
  route: HighDensityRoute,
  connMap: ConnectivityMap,
): boolean => {
  const routeIds = [route.connectionName, route.rootConnectionName].filter(
    (id): id is string => id !== undefined,
  )

  // Same-net pads and copper should not block via removal collision checks.
  return routeIds.some((routeId) =>
    obstacle.connectedTo.some(
      (connectedId) =>
        connectedId === routeId || connMap.areIdsConnected(connectedId, routeId),
    ),
  )
}

Inputs: obstacle, route, and connectivity map. No hidden instance state.

routeIds: all ids that identify this route electrically.

Comment: explains the non-obvious PCB rule.

obstacle.connectedTo: ids the pad/copper says it belongs to.

connectedId === routeId: direct match.

areIdsConnected: indirect same-net match.

3. Endpoint proof stays strict

This is intentionally different. A same-net sibling pad can be safe to ignore as a collision blocker, but it must not prove that this route endpoint supports another layer.

obstacleIsRouteEndpoint 
const obstacleIsRouteEndpoint = (
  obstacle: Obstacle,
  route: HighDensityRoute,
): boolean => {
  const routeIds = [route.connectionName, route.rootConnectionName].filter(
    (id): id is string => id !== undefined,
  )

  return routeIds.some((routeId) => obstacle.connectedTo.includes(routeId))
}

No connMap here: that is the point.

Exact endpoint only: the obstacle must directly name this route or root.

Why: same-net sibling pads should not authorize moving this route endpoint to another layer.
