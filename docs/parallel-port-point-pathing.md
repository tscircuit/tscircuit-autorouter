# Parallel port-point search

The optional TypeScript backend is isolated in `tiny-hypergraph/lib/core-parallel`; workers and snapshot management live under `lib/parallel/`. The ordinary entry excludes worker code. No WASM, native kernel or native build tool is used.

Four persistent workers run the original distance-aware A* on private, consistent graph snapshots. The coordinator commits routes in their original order. Workers search upcoming routes while the current route completes, within a four-route lookahead window. A worker slot is reserved for a stale-head retry while other slots prefetch, avoiding both head starvation and excessive work past a rerip. Worker frontiers store hop IDs, costs and predecessors in numeric arrays, while preserving the original indexed heap comparison, tie order, scoring and logical iteration counts. Candidate objects are created only when returning a path. The serial solver is unchanged.

Completed work is first validated against its entire region read set. When versions changed, a winning path can still be reused if all intervening updates were additive, its ports remain legal and every segment retains exactly the same cost. A stronger certificate also permits unavoidable uniform increases in the chosen source region and the reachable goal regions: it reprices the path and accepts it only when its increase is bounded by the increase that every alternative must pay, within floating-point tolerance. A zero-length transition isolates the uniform marginal region cost; tests validate that this increase lower-bounds all transition increases. Under the nonnegative intersection/via and quadratic density model, adding segments or congestion cannot reduce transition costs. An old minimum path whose cost is unchanged therefore remains minimum. Releases, removals, reordered segments and congestion decreases advance an invalidation generation. Work from an incompatible generation is canceled or rejected; changed path costs and assignments require a fresh search. Errors propagate.

The default parallel policy additionally allows a legal cached path whose repriced cost is at most 1.05 times the updated A* lower bound. This bounds per-route cost inflation at 5% under the nonnegative monotone model, up to floating-point tolerance; it does not assert a global routing-quality bound. Set `{ maxRelativeCostIncrease: 0 }` as the fourth argument to `solveWithParallelSearch` for exact-cost certificates only. The serial solver remains unchanged. Full-pipeline DRC is required to assess downstream outcomes.

The coordinator charges accepted search iterations against the existing logical budget. Speculative searches can perform extra physical work; metrics report this separately. Existing partial-route searches retain their serial implementation. Completion candidates use the asynchronous route backend. Runtime leases reserve the persistent group and release workers before later pipeline stages.

Bun and Node workers register `ParallelRouteSearchTask` explicitly. The runtime's verified persistent worker count enables this backend. Initialization uses the original constructor boundary, matching the base revision.

Metrics include acknowledged workers, actual participating workers, concurrent searches, charged expansions, speculative searches/expansions, stale results, accepted path certificates, worker search/snapshot time and graph synchronization time.

Validation covers weighted path costs, valid committed segments, overlapping nets, certificate reuse after additions, rejection of blocked paths and increased costs, invalidation after removals/releases, logical budgets, completion, worker failures, shared runtimes and entry-point isolation. The autorouter checks bundled and packed Bun/Node/browser consumers.

## Performance status

The prior synchronous hop-owner design did not meet the target. Full dataset18 [run 40476046145](https://github.com/tscircuit/tscircuit-autorouter/actions/runs/40476046145), tiny-hypergraph `c8d64f2` / autorouter `baf7703e`, measured 149.616s → 141.915s summed port-point time (1.054x), with all 16 solved/DRC passing, while end-to-end time regressed 597.918s → 639.515s. Its near-2x sample-6 result was not representative.

The later asynchronous hop-owner prototypes failed sample 14 in repeated phase checks and were discarded. Those results do not describe the current route-level implementation.

The first original-search/path-certificate revision passed all 16 phase solves but measured only 1.122x against its one-worker backend (206.740s → 184.248s; run 40487403139). Three sample-14 pairs retained identical output and measured no gain (run 40487398346). The current packed-frontier/terminal-certificate revision requires fresh Blacksmith measurements. The target remains 2x faster summed `portPointPathingSolver` time against base at four threads, with unchanged solve/DRC outcomes. The packed optimal-certificate revision measured only 1.061x in the one-worker/four-worker phase comparison (122.844s → 115.791s, all 16 phase inputs solved; run 40491667218). Its full base/head comparison is separate. The current four-route/bounded-reuse revision requires new measurements; no gain is claimed while its results are pending.

Run benchmarks on Blacksmith per repository policy. `/benchmark --dataset 18 --threads 4` compares both revisions on the same machine. The manual `Port-point parallel scaling` workflow runs isolated one-worker/four-worker pairs. It retains all failures and exits unsuccessfully when outcomes regress. Phase-only measurements do not validate downstream DRC; use the full pipeline comparison for that.
