BgaTopologyGeneratorSolver

This solver converts a BGA-like component's SRJ obstacle field into coarse routing regions. It does not route traces itself. It builds a topology that later planners and pathing solvers can use.

Execution Flow

1. Filter

Keep obstacles whose bounding boxes overlap the SRJ bounds.

2. Infer

Cluster obstacle centers to count rows and columns.

3. Emit

Create mesh nodes, clone obstacles, publish stats, mark solved.

Normal BGA Path

When at least one row and one column are inferred, the shared helper builds exact grid edges from the board bounds and every in-bounds obstacle boundary. It then walks every cell between adjacent X and Y edges.

Obstacle cell: if a cell exactly matches an obstacle rectangle, emit one node spanning all available layers.
Diagonal free-space cell: if a free cell is surrounded by obstacle cells diagonally, emit one multi-layer node. This preserves useful diagonal escape regions.
Regular free-space cell: emit one node per z layer, so same-XY space is represented independently on each layer.

Source: bgpTopologyGeneratorShared.ts lines 270-555.

Fallback Ring Path

If clustering finds no rows or no columns, there is no meaningful BGA grid. The helper falls back to a ring: four corner diagonal regions and four side regions. The split is at 25 percent from each board edge.

Corner diagonal nodes usually span all layers. If a diagonal region overlaps an obstacle on any candidate layer, it is split into one node per layer. Side regions are always emitted one per layer.

Source: bgpTopologyGeneratorShared.ts lines 161-268 and 513-520.

Important Details

Layer handling

getLayerRange(layerCount) returns numeric z layers from 0 to layerCount - 1. Obstacles can provide explicit zLayers; otherwise their named layers are mapped to z values.

Jitter tolerance

clusterAxisValues sorts axis values and groups nearly equal values. Its tolerance is one quarter of the smallest real gap, with a tiny lower bound.

Obstacle detection

A region contains an obstacle only if their boxes overlap with positive width and height, and if at least one candidate z layer matches the obstacle's z layers.

Stats

The solver records component identity, layer count, inferred row and column counts, multi-layer node count, side node count, and total mesh node count.

Mental Model

Think of the solver as a component-local topology slicer. It sees pads and obstacles, draws vertical and horizontal cuts through their edges, and labels every resulting rectangle with the layers on which routing can reason about it. The original obstacles are preserved separately so later stages still have exact geometry, while routing regions provide a coarse graph-friendly space model.
